# skywave

This file records the design system that already exists in `apps/web/src/app/globals.css` and the components that use it. All tokens are in `:root` at the top of that file, and the two fonts are loaded from Google Fonts in `apps/web/src/app/layout.tsx`. Nothing here is aspirational: where the code is inconsistent, the relevant section says what the code does and lists the gap under **Known gaps**. When the code changes, update this file.

## Overview

skywave plays public KiwiSDR receivers in the browser. You tune shortwave broadcasters and ham bands, watch the signal on a waterfall, and pick a receiver from a list or a greyline map (README). It's a personal tool (the map design record calls it builder mode) for a listener who wants sound quickly.

The page is drawn as a radio console. The page is enamel teal (`--enamel`), and the "one loud thing on the page" (globals.css comment) is a celadon glass dial (`--glass` → `--glass-shade`) with a red needle (`--needle`). Primary controls are brass (`--brass`). Live state, links, focus and the tuned frequency light up amber like a pilot lamp (`--lamp`). Instrument text (wordmark, readouts, headings, dial numerals) uses a condensed face, Barlow Condensed. Running text uses Atkinson Hyperlegible. `color-scheme: dark` is set, and there is no light theme.

Page order (`page.tsx`): header strip (wordmark with the UTC clock beside it, "Listening via …" or the receiver choice, **change**, **IBP beacons** (`.tuned-to-beacons`, opens the drawer with the beacon strip expanded and focused), **GhostNet** (`.tuned-to-ghostnet`, the same for the GhostNet strip; it leaves beacon mode alone), Listen/Stop) → receiver drawer (the Receiver form, then the Receivers section: help sentence, Pick best bar, map, the folded IBP beacon strip, the folded GhostNet strip, folded table; then the listener's name field, `IdentField` (`.ident-field`, a 28rem-wide text input with a 0.85rem `--muted` `.ident-note` under it that previews the name or says what's wrong, and a `--lamp` border while invalid); collapsed unless opened) → dial → controls (readout, modes, S-meter, volume, and the audio spectrum from the first audio) → the sticky tuning bar (#90; hidden until the modes scroll up under it) → status row (with Back, Tap to resume audio while the browser holds the sound stopped, and Pick best on errors) → waterfall → presets → find a station → signal stations → strong signals now (each of these four folds under its heading; see **Collapsible sections**). Choosing a receiver lives at the top but takes one line until it's wanted (UI critique, replacing design D3's receivers-last order); the instrument and its live output still sit together, so turning the dial and watching the waterfall happen in one view. Both pages end with `SiteFooter` (`.site-footer`: 0.85rem `--muted` text above a `--rule` line), the credit "Built by Jason Shultz · Source on GitHub · For Kiwi owners", then **Cookie settings** (`CookieSettingsButton`, only where `NEXT_PUBLIC_GTM_ID` is set; it reopens the cookie bar); on the listening page every link opens a new tab so following one never stops the audio. `/owners` (`app/owners/page.tsx`) is running text for KiwiSDR owners in the same frame: the wordmark (a link home) in `.console-header`, then `.owners-body` (68ch wide) with a Barlow `.owners-title` (2rem) and section `h2`s styled like the console's (1.6rem, `--glass`). The signal station pages, `/signals` and `/signals/<slug>` (#103), reuse that frame (see **Signal station pages** under Components). Visually hidden `h2`s "Tuner" (before the dial) and "Waterfall" let screen readers reach the instrument by heading.

**Sticky tuning bar** (`TuningBar.tsx`, `.tuning-bar`, #90): once the mode buttons have scrolled up under where the bar sits, a bar pins to the top of the window (`position: fixed`, `--enamel-raised`, a `--rule` bottom line, 1120px wide like the console): the frequency in lamp digits (Barlow 600, 1.6rem, read-only), the four modes as `aria-pressed` buttons styled like the main ones, the receiver as a dotted-underline button showing what the header strip shows (cut with an ellipsis; named "<that text>, change receiver"), above 860px the UTC clock in its compact form (`.tuning-bar-clock`, grid area `clock`: "14:05 UTC", Barlow 600 1.15rem tabular `--text` with "UTC" 0.85rem `--muted`, not focusable; hidden at ≤860px, where the receiver needs the room), and Listen/Stop (`PowerButton`, shared with the header). One row at desktop widths; at ≤520px two rows, frequency, receiver and Listen/Stop, then the modes. Its height is `--tuning-bar-h` (3.75rem, 6.75rem at ≤520px), which is also the page's `scroll-padding-top` while it shows, so keyboard focus never lands under it. An invisible sentinel from the top of `.console` to the modes decides when it shows; keyboard focus inside keeps it up until focus leaves. Hidden is the `hidden` attribute, so it is out of the tab order and the accessibility tree. The receiver button opens the drawer (like **change**, it drops a beacon Listen waiting on the clock), scrolls to the top and focuses the drawer; a Listen from the bar that can't start, or that ends in a receiver's error once Pick best has nothing left to try (with focus still on the bar or on nothing, and nothing done since), focuses the status row that says why.

**Map tokens.** `--map-sea`, `--map-land`, `--map-rule`, `--map-dot` and `--map-playing` are aliases (`var(--enamel-deep)`, `var(--enamel-raised)`, `var(--rule)`, `var(--glass)`, `var(--lamp)`). `--map-night` (0.31) and `--map-twilight` (0.2) are black overlays that together make about 0.45 (CSS comment). `--map-last` is glass at 45% alpha. `--map-beacon` aliases `var(--brass)`: IBP beacons (filled on the air, a 60% ring otherwise; the selected one larger with a `--needle` ring), their labels, and the dashed great-circle path from the selected beacon, which sits under the receiver dots. Brass is about 4.2:1 on `--enamel-raised`, so the beacon strip's callsigns use `--text` and only the legend glyph (`.key-beacon`) is brass. `receiver-map-style.ts` reads them with `getComputedStyle` (`TOKEN_VARS`), and reads `--needle` and `--lamp` directly for the listening ring and the dot labels. Its `FALLBACK_TOKENS` copy the same values for tests or an unreadable stylesheet.

**Alpha tints used inline** (no token): brass 12% for outline-button hover `rgba(193,154,75,0.12)` (Pick best, presets Save); lamp 35% for text selection `rgba(242,197,92,0.35)`; glass 8% for table-row hover and the waterfall passband (16% over the trace); glass 45% for passband edges; enamel-deep 82–85% for `.map-overlay` and `.map-chip`; needle 85% dashed for the waterfall center line; danger 10% for preset delete hover; lamp 32% radial glow at the bottom of the dial.

**Browser surfaces.** Text selection is lamp at 35% with `--text` (`--ink` on the dial glass), inputs use a `--lamp` caret, and the page, the dial strip and the receiver table's scroll box use `scrollbar-color: var(--rule) var(--enamel-deep)` (browsers that ignore `scrollbar-color` keep their own).

**Known gaps**

- `--map-last` restates glass as a literal rgba instead of deriving it from `--glass`. `receiver-map-style.ts` reads the token's text and hands it to MapLibre, which can't parse a `color-mix()` or relative color, so a derived value would break the map.

## Typography

Two faces, loaded in `layout.tsx` with `display=swap`:

- **Atkinson Hyperlegible** (`--font-ui`, fallback `system-ui, sans-serif`), weights 400 and 700. Used for body text, form fields, buttons, status, table cells, help and meta text. Base size 16px with line-height 1.5 on `html, body`. Weight 700 goes on buttons (`.power`, `.pick-best`, presets Save, `.map-listen`) and `.status-state`.
- **Barlow Condensed** (`--font-instrument`, fallback `"Arial Narrow", sans-serif`), weights 500 and 600. Used for the instrument face: wordmark (2.6rem/1, 0.01em), frequency readout (3rem/1, tabular numerals; 2.6rem at ≤860px), section `h2` (1.6rem), the "All receivers" summary and map heading (1.15rem), mode segments (1.1rem), S-meter reading (1.5rem), preset frequency (1.2rem, tabular) and mode (0.95rem), the UTC clock's digits (600, 1.6rem in the header, 1.4rem at ≤520px, 1.15rem in the tuning bar, tabular), map card names (1.05rem), readout unit (1.3rem), the tuning bar's frequency (1.6rem/1, tabular) and modes (1rem), dial numerals (15px/500, majors 22px/600), dial band labels (12px/600), S-meter scale (0.8rem), waterfall axis (0.9rem) and audio spectrum ticks (0.75rem). Barlow headings use weight 600 and color `--glass`. Every Barlow use names a loaded weight: `.readout-unit`, `.preset-mode`, `.smeter-scale`, `.waterfall-axis` and `.audio-spectrum-axis` use 500.

Sizes in use for UI text: 1rem (body: the receiver list's state line, which "reads at body size", the table, status, waterfall empty text, receiver help, checkboxes, `.link-button`) and 0.85rem (small: field labels and the Receiver field's chip and hint, meta, legend, map notes, receiver host, the span picker, station names under the readout and on the waterfall, the letter-keys switch label, the UTC clock's date line and "UTC", the saved-frequency stamp), plus 0.8rem for the S-meter overload and waterfall unit. The dial's row labels ("Broadcast", "Amateur") are Atkinson 11px italic, `--muted`, set vertically in a gutter left of the glass.

Numbers that change in place use `font-variant-numeric: tabular-nums` (readout, the tuning bar's frequency, the UTC clock's digits, preset frequency, table `.num` cells).

Times come in two styles on purpose (#106/#107): the live clocks write `HH:MM:SS` or `HH:MM` with colons, like a clock face; the saved stamp writes `HHMM UTC`, the radio-schedule style of the GhostNet strip. (Find a station writes its start times with a colon, "19:00 UTC".) The clocks and the stamp take their UTC dates ("Mon 23 Nov", "8 Nov", "8 Nov 2025") from `utcDate` in `lib/utc-time.ts`; the beacon strip still writes its own.

Map dot labels are not Barlow. MapLibre draws them in Noto Sans Bold 12px uppercase, because "the page's Barlow isn't available as map glyphs" (`receiver-map-style.ts`).

**Known gaps**

- The map design record says map labels are Barlow Condensed and the legend is 13px. The code uses Noto Sans Bold and 0.85rem.

## Layout

- **Page frame:** `.console` is a single-column grid, `max-width: 1120px`, centered, padding `24px 16px 64px`, `gap: 20px`. The header (#173) is a three-column grid, `auto minmax(0, 1fr) auto` (gap 12px 20px), so the strip's length never moves Listen/Stop: the button keeps the first row's right end whether the strip shows the Auto chip or a long "Listening via" line, which cuts with its ellipsis or wraps its links inside its own column. The wordmark and the button hold the row's top (`align-items: start`) and only the strip centers, so a strip that wraps to a second line doesn't nudge them down. At ≤45em (720px at the default 16px text; in em so a larger default font moves the switch out with the wordmark and button rather than squeezing the strip's links under Listen/Stop), where the strip's column would shrink to a few words with its links stacked deep, the grid goes to two columns (`minmax(0, 1fr) auto`) and the strip moves to a second row across both (`grid-row: 2`, `grid-column: 1 / -1`): the wordmark and clock with Listen/Stop at the right end, then the strip across the full width. The strip is placed rather than given a two-row template, so `/owners` and `/signals`, whose header holds only the wordmark, get no empty row or gap; their wordmark link (`.owners-wordmark`) has `justify-self: start` so it keeps its text width in the grid instead of stretching across the header. At ≤520px the header goes back to a wrapping flex row (centered), keeping the phone order: wordmark and clock, then the strip, then Listen. In order: `.brand-row` (the wordmark and, beside it, the UTC clock `UtcClock.tsx`, #106: a `<time>` with the UTC weekday and date over the 24-hour time, "Mon 23 Nov" in Atkinson 0.85rem `--muted` over "14:05:09" in Barlow 600 1.6rem tabular `--text` and a 0.85rem `--muted` "UTC"; the server-corrected time, ticking each second with no animation and no live region; never lamp, so it stays quieter than the readout; before mount it holds its exact space with hidden stand-in text, the date line set to `contain: inline-size` so only the tabular time line sets the clock's width; the two share one row (`align-items: last baseline`, gap 20px, 12px with 1.4rem digits at ≤520px), and the row wraps the clock under the wordmark only when it can't fit, such as a 320px phone before the condensed font loads, so the page never scrolls sideways; the clock is a sibling of the `h1`, not inside it), the strip (`.tuned-to`: while a receiver plays, "Listening via **<place>** · <host>" (`.tuned-to-text`, muted, with `.tuned-to-place` in `--text` 700 and `.tuned-to-host` muted 400, hidden at ≤520px; just the host, in `--text` 700, when the list has no place), otherwise the receiver chip without its ✕; then **change**, an inline link button named "Change receiver" with `aria-expanded`, 44px tall on touch at any width, then **IBP beacons** (`.tuned-to-beacons`) and **GhostNet** (`.tuned-to-ghostnet`), inline link buttons that open the drawer with that strip expanded), and Listen/Stop, which submits the drawer's form (`form="receiver-form"`). The drawer (`#receiver-drawer`, `.drawer`, labelled "Choose a receiver") is an `--enamel-raised` panel with a rule border and 16px padding. Closed, it is `inert` and collapses to nothing (`.drawer[inert]`: height 0, `visibility: hidden`, and a negative `--console-gap` margin to cancel the grid gap) rather than unmounting, so a loaded map keeps its size. It starts shut on every visit, a first one included, so the dial and Listen are on the first screen (on a first visit the table inside is already open for when **change** is pressed); it opens by itself only when a blank Listen can't pick (the list hasn't loaded: the message points at the field and Try again inside); choosing a receiver in it (table, map, Switch or Enter, Pick best) closes it and moves focus to **change**. The map isn't admitted until the drawer has opened once. In the drawer, the Receiver field's choice chip sits on the label row (`.field-head`), opposite the label, so the inputs stay bottom-aligned: "Auto (best for this frequency)" (`.chip.chip-auto`, muted) or the pinned receiver's name (`.chip-label`, ellipsis at 24ch) with a ✕ (`.chip-unpin`, 22px, a 44px hit area on touch); both chips are 26px tall, so pinning doesn't move the header. After the chip, the hint "or type an address" (`.field-hint`, 0.85rem muted) stays visible, typed address or not; the row wraps when narrow. The chip's text and the hint are the input's `aria-describedby`. The fields stay editable while listening; when they name a receiver other than the one tuned, a **Switch** button (`.receiver-switch`, rule border on `--enamel-deep`, quieter than Listen) appears before Listen/Stop. "Switch to a better receiver?" (`.switch-prompt`, a live region) sits under the status row on a reserved line: plain text plus two inline link buttons. Either button moves focus to the status row, since it goes away with the offer. The reception question (`ReceptionPrompt.tsx`, issue #60) shares that reserved line when no offer is showing: after a minute of audio on a frequency the EiBi schedule lists (never naming a numbers station Priyom's schedule drives, #148), on a receiver from the public list (never one typed in), "Did you hear KBS World Radio on the receiver in Seoul on 9,580 kHz?" (two or three stations: "anything from A, B or C"; a receiver the list doesn't know: "the receiver at <host>"; after a signal station's Listen, #101, or with the dial on a frequency where one catalog station is the only one on the air, #148, the station instead, with WWV and WWVH told apart by voice: "Did you hear WWV (a man's voice) …?"; hand-tuned to a frequency two or three catalog stations are on, #150, "Which did you hear on the receiver in … on 10,000 kHz: WWV or WWVH?" with **Heard WWV (a man's voice)**, **Heard WWVH (a woman's voice)**, **Heard both**, **Heard nothing**, **Something else / can't tell** and **Didn't open** in place of the three answers; a row marked "season schedule, not confirmed" is never asked about), then **Heard**, **Not heard** and **Didn't open** as inline link buttons in `.reception-answers`, an **Add a comment** link that swaps in `.reception-comment` (a small field, 280 characters), and a 22px `.reception-close` ✕ styled like `.chip-unpin` (44px hit area on touch). An answer shows "Thanks for the report." for 4 s; an answer or the ✕ moves focus to the status row. Unanswered, it goes away after 4 minutes (the server takes answers about a listing on air in the last 5). It never stops or retunes anything.
- **Controls:** `.controls` is a 4-column grid `auto auto minmax(220px,1fr) minmax(140px,200px)` (readout, modes, S-meter, volume), gap `16px 28px`, padding `16px 20px`.
- **Spacing:** no spacing tokens exist. Gaps and paddings are literal px values. The common ones are 10, 4, 6, 16, 8, 20, 14 and 12px (in order of use), with 2px for tight label stacks. The front matter `spacing` group lists these values, named by size.
- **Dial width:** `.dial-glass` has `min-width: 860px` (`--glass-min`, set on `.dial-frame`, which also sizes the row-label gutter) inside `.dial-scroll` (`overflow-x: auto`), so below that width the dial scrolls sideways and `Dial.tsx` scrolls to keep the needle in view.
- **Scroll regions:** the receiver table scrolls on its own (`max-height: min(60vh, 520px)`) "so the dial stays near the top of the page", with sticky headers and `scroll-padding-top: 2.5rem`.
- **Map height:** `--map-height` is 360px, 300px at ≤860px and 220px at ≤520px. `.map-frame` reserves `min-height: var(--map-height)` from the first render "so nothing jumps when the map arrives". `.map-header` is held at `min-height: 44px` so the Center button appearing doesn't push the map down.
- **Breakpoint 860px:** `--map-height: 300px`; controls go to two columns, with the readout and modes spanning both; readout 2.6rem.
- **Breakpoint 45em (720px at 16px text):** the header's strip moves under the wordmark and Listen/Stop, across the full width (#173). The one breakpoint written in em, so it follows the text size.
- **Breakpoint 520px:** the header goes from its three-column grid back to a wrapping flex row (#173); controls go to one column (padding 14px); the readout aligns left and, where `field-sizing` is supported, shrinks to its digits; the host field goes full width; the table's Location column is hidden; table-wrap padding drops to 12px; the open waterfall canvas drops from 240px to 180px; `--map-height: 220px`; the map card docks under the map (`position: relative`, `max-height: 240px`, top border only, no radius). ## Elevation & Depth

Depth comes from three enamel tones, not shadows:

- `--enamel-deep`: recessed wells (inputs, waterfall, S-meter track, map frame, focused readout).
- `--enamel`: the page, plus surfaces that float over the map (card, tooltip, MapLibre controls), which sit on the deep map.
- `--enamel-raised`: panels on the page (`.controls`, `.receivers-table-wrap`, the sticky tuning bar).

Stacking on the map: `.map-tooltip` and `.map-card` sit at `z-index: 3`, "above MapLibre's controls (z-index 2)". The sticky table header is at `z-index: 1`. The sticky tuning bar is at `z-index: 10`, above both. `.map-overlay` is a translucent enamel-deep scrim (0.82) with no blur. No `backdrop-filter` is used anywhere.

The only real glass effect is the dial (`.dial-glass`):

- A vertical gradient from glass to glass-shade.
- A lamp-amber radial glow from below (`rgba(242,197,92,0.32)`).
- An inner 1px ink edge at 35% and an inner white highlight (`inset 0 8px 18px rgba(255,255,255,0.35)`).
- A 6px `--enamel-deep` ring that reads as a bezel (`0 0 0 6px`).

Other shadows:

- The listening status lamp glows (`box-shadow: 0 0 8px var(--lamp)`).
- Table headers use `inset 0 -1px 0 var(--rule)` as a bottom border that moves with the sticky cell.

## Do's and Don'ts

Rules the code follows:

- **Do** show keyboard focus as a 2px `--lamp` outline at offset 2px (global `:focus-visible`). It's restated on `.map-frame` and on the mode span (whose radio input is invisible). The only deviations have a stated reason: offset 8px on the dial, −2px inside the table's scroll box ("The scroll box clips anything outside it, so draw focus rings inside"), and the readout, which swaps the outline for a lamp border on focus.
- **Do** use `--lamp` for "this is live / this is the one": the listening lamp, the tuned table row, the current preset, the map's listening dot. Connecting reuses lamp but dimmer (0.5 opacity lamp; a ring instead of a dot in the table and on the map).
- **Do** keep `--needle` for the tuning position: the dial needle, the waterfall center line, the listening dot's ring.
- **Do** keep `--danger` for failures and warnings (error status, overload, old list, delete hover).
- **Do** honor `prefers-reduced-motion`. It removes the S-meter fill transition, the waterfall's growth from strip to full height, the tuning bar's 180ms slide down as it appears, and the map fade-in. In JS (`prefersReducedMotion` in `lib/reduced-motion.ts`), `ReceiverMap.tsx` skips the 600ms dot emphasis and uses `jumpTo` instead of `easeTo`, and zooms with duration 0; `Dial.tsx` scrolls the strip to the needle without smoothing; and the tuning bar's receiver button jumps to the top of the page instead of scrolling there smoothly.
- **Do** reserve space for content that arrives late: `.map-frame` min-height, `.map-header` at 44px, `.receivers-updated` at `min-height: 1lh`, `.status` at `min-height: 1.5em`, `.switch-prompt` at `min-height: 1lh` (an offer that wraps on a phone can still add a line), each live Signal stations row's `.signals-heard` at `min-height: 1lh` (1.5em fallback) with no wrapping, a station page's `.signal-live` at `min-height: 1.5em`, `.chip` at `min-height: 26px` (Auto and a pin are the same height), and the header's own grid column for Listen/Stop (#173), so "Listening via …" arriving with a long place or host can't push the button just pressed. The one deliberate exception is the visit's first audio, after the listener pressed Listen: the waterfall strip grows, the span picker appears above it and the dial goes compact, once, together. Opening and closing the receiver drawer moves the page too: when asked, and when a blank Listen can't pick.
- **Do** keep an inline link at the line's height while giving it a 44px tap target on phones (padding plus a matching negative margin).
- **Do** put a costly action on its own line, away from cheap ones. The map overlay's "Reload page (stops the radio)" sits in `.map-overlay-costly` with `margin-top: 16px`, below Retry and Browse.
- **Do** dim disabled buttons with `opacity: 0.45` and `cursor: default` (`.pick-best`, presets Save, `.map-center`, `.map-listen`, `.link-button`).
- **Do** give touch its own hint with `.hint-coarse` (`aria-hidden`) beside a `.hint-fine` sentence that stays readable to screen readers.
- **Do** use tabular numerals for frequencies and counts that update in place.
- **Don't** style the map from hard-coded colors. Colors come from the `--map-*` tokens (plus `--needle` and `--lamp`) through `resolveTokens`, with `FALLBACK_TOKENS` kept equal to `:root`.
- **Don't** add drop shadows to panels. Depth comes from the enamel tones. The only outer shadows are the dial bezel ring and the status lamp glow.
